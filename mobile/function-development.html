移动端 · 功能开发 ​

以「新增一个业务页面并接通接口」为主线。蓝本 delivery-template-uniapp。

新增页面完整流程 ​

  1. 建页面文件：在对应分包下建模块目录，页面三件套（index.vue + detail.vue / edit.vue 按需 + lang.js）：

    text
    subPages/business/qual_mgmt/<模块名>/
├── index.vue      # 列表主页（统一命名 index.vue）
├── detail.vue     # 详情页（按需）
├── edit.vue       # 编辑页（按需）
└── lang.js        # 本模块词条

  2. pages.json 注册：在对应 subPackages[].pages 里加一条，path 写全分包相对路径（如 business/qual_mgmt/<模块名>/index）。不注册的页面无法导航；

  3. 权限绑定：移动端菜单与按钮权限由服务端运行时下发——在运营端「菜单元数据」登记新页面菜单并绑定到租户资源，前端不做路由表（无前端路由守卫，页面可达性 = 菜单下发）。

请求层用法 ​

基本调用 ​

业务接口写在模块 api.js 或全局 api/ 中，函数以 Api 结尾，经 utils/request.js 发出：

js
// 参考 api/user.js 的写法
import request from '@/utils/request'

export const loginApi = (data) =>
  request({ url: '/login/identifier', method: 'POST', data, header: { 'content-type': 'application/x-www-form-urlencoded; charset=UTF-8' } })

utils/request.js 自动做的事（开发者无需重复处理）：

  • 请求头注入：Token-Type: 'APP'、Authorization（storage 的 Token）、accountId、tenantId、timeZone、lang、tenantlang（均可被 options.header 覆盖）；
  • 无 token 拦截：除白名单（/login/captcha、/captcha）外，无 token 直接 reLaunch 到登录页；
  • 响应剥壳：成功时 resolve(data.data)，业务代码拿到的是纯数据；statusCode !== 200 会 toast 报错并 reject；
  • 登出处理：302 / 401 自动调用 logout({ showModal: true })（清存储但保留语言与记住密码，回登录页）；
  • /app 前缀改写：每个 URL 先经 needsPrefix() 计算（见下）。

prefix-rules：多客户前缀改写 ​

utils/prefix-rules.js 是移动端多客户的请求层核心：按当前请求域名匹配客户规则，把 /app 改写成 /app{addPrefix}：

js
export const PREFIX_RULES = {
  st: { domains: ['sa.matchbim.cn', 'sa.dev01.matchbim.cn', /* … */],
        addPrefix: '/sa',
        routes: ['app/labors/record/query/page', /* … 仅特定路由改写 */] },
  cl: { domains: ['cl.matchbim.cn', 'cl-backup.matchbim.cn', /* … */],
        addPrefix: '/cl', routes: [] },   // routes 为空 = 全部请求改写
}

匹配逻辑：① 域名命中规则 → ② 剥掉路径开头的 /app → ③ 已带该前缀则跳过（防重复）→ ④ routes 逐条匹配（支持 {xxx} 占位），命中才返回前缀。

  • 新客户接入：在 PREFIX_RULES 加一条规则（新客户域名 + 前缀）；不加规则的客户走原样 /app；
  • 个别接口不想被改写：请求传 options.skipPrefix: true。

token 与登出 ​

  • utils/auth.js：Token 读写删（storage 键 Token，底层 Cache 封装）；
  • utils/logout.js：logout() 清存储（保留语言与记住的密码），默认弹窗确认后跳 /subPages/system/login/index。

菜单与按钮权限 ​

  • 运行时下发：菜单树、页面可达性、按钮权限全部来自服务端（与 PC 端同一权限模型）；
  • 开发时申请新权限项：在运营端「菜单元数据管理」登记菜单 → 项目资源配置中勾选 → 菜单分类中勾选（与 PC 端动态路由三步一致），按钮权限在按钮配置中登记权限码；
  • 按钮权限写法：用权限感知组件 pap-button（原生 button 封装，无权限自动不渲染），权限码由 constants/permissions.js 的 definePermission() 生成 13 种标准码（query/add/edit/delete/export…）；
  • 详细规则见规范篇：按钮权限规则、菜单分组权限同步。

i18n 接入 ​

  1. 模块内建 lang.js，导出 { zh: {…}, en: {…} }（key 用中文原文）；
  2. 在 locale/zh.js / en.js 登记词条（当前规模：zh 约 113 条 / en 约 127 条）；
  3. locale/AppLang.js 聚合后由 App.vue onLaunch 经 initI18n 装载；页面里 t('中文原文') 取词，zh 态直接返回 key 本身，en 态查表（缺词回退原 key 并 console 报错）。

与 PC 端的差异

移动端是自研 mixin 方案（utils/mixin.js），package.json 里的 vue-i18n 是未使用的声明；PC 端是 i18next/vue-i18n 分域懒加载。两端词条不通用，跨端移植需人工搬运。
