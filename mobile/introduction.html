移动端 · 入门 ​

蓝本项目：weChat-applet/delivery-template-uniapp（模板工程，versionName 2.4.2 / versionCode 20402）。客户项目由复制派生（changjin / changshen / qinghua / g108 等）。

平台定位 ​

工地移动端「4S SiteSecure Mobile」——E9 工地业务在手机侧的入口，与 PC 端（Keystone 2.0）同后端、同租户、同权限模型：

  • 后端同一套（*.matchbim.cn 体系），移动端接口统一挂在 /app 前缀下；
  • 登录用户、租户（请求头 tenantId）、按钮权限均由服务端下发，与 PC 端共用权限模型；
  • 多语言（zh / en）与 PC 端共用词条语义。

一码多端：微信小程序 + App（Android） ​

uni-app 一套代码编译到微信小程序与 Android App 两个目标，平台差异用条件编译隔离（#ifdef MP-WEIXIN / #ifdef APP-PLUS）：

  • App 端原生模块（manifest app-plus.modules）：Share、Geolocation、Barcode、Camera、iBeacon、Maps、Push（unipush 2，含离线推送）；
  • 小程序端：使用微信播放器插件（ezplayer / tplink-player / imou-player，见 manifest mp-weixin.plugins）等微信原生能力；
  • 发版差异：App 走整包安装包 + wgt 热更新（utils/version-manager.js + components/app-upgrade）；小程序走版本更新机制（见规范篇小程序版本更新）。

多客户机制：运行时（与 PC 编译期相对） ​

维度PC 端（Keystone 2.0）移动端（本模板）
客户差异实现编译期：VITE_BUILD_VIEWS 按客户裁剪业务视图运行时：服务端下发菜单树与按钮权限
请求指向pnpm switch:api 切换 API 基址utils/prefix-rules.js 按域名改写 /app 请求前缀（sa / cl 客户）+ 请求头 tenantId / lang
页面未选中业务不参与编译页面全量打进 subPages/ 分包，客户 A 的页面代码对客户 B 可见（涉敏感逻辑注意）
交付方式每客户一个仓库副本复制模板工程派生 + 服务端配置菜单/权限

读者指引 ​

  • 新人：入门 → 技术栈 → 快速开始（半天内跑起小程序）→ 项目结构 → 功能开发；
  • 只做微信小程序：跳过快速开始的「App 打包与发布」一节；
  • 只做 App：额外细读快速开始的「App 打包与发布」与规范篇「小程序版本更新」；
  • 从 PC 端转来：先读上面「多客户机制」对照，理解运行时权限与编译期裁剪的差异；i18n 机制两端完全不同（自研 mixin vs i18next/vue-i18n），见技术栈。
