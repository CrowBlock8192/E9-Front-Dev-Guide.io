移动端 · 项目结构 ​

以 delivery-template-uniapp 为蓝本。原始版《目录结构详解》已迁入参考文档，本文以其为底稿并修正了与当前代码的偏差（分包已从 4 个演进为 9 个、主包瘦身等）。

顶层目录职责 ​

目录职责
api/全局公共 API（6 文件）：user / dept / dict / equipment / subitem / common
components/自研 pap-* 业务组件族（14 个）+ app-upgrade、message-banner，easycom 自动注册
config/仅 index.js：按平台与环境选 baseURL + 三方密钥（高德 / TPLink / 乐橙 / OSS）
constants/仅 permissions.js：definePermission() 生成 13 种标准按钮权限码
libs/三方库本地离线包：dayjs、echarts 5.6.1、timezone、utc（不走 npm）
locale/i18n 词典：AppLang.js（聚合入口）+ zh.js（约 113 条）+ en.js（约 127 条）
pages/主包页面，当前仅 index/（index.vue + lang.js，即首页/功能入口）
subPages/分包页面实体（9 个分包，122 页，见下）
static/仅 images/（common / index / mine / navbar / notice / quality 图标）
styles/index.scss（全局 page 样式）+ mixin.scss（to-rpx、gap 兼容）
utils/14 个工具模块：request、prefix-rules、auth、cache、md5、permissions、version-manager、logout、mixin（i18n）、uview（桥接）等
uni_modules/uview-ui 2.0.38（本地迁移版）+ xe-upload 1.0.2
docs/项目内历史文档（已迁入本站，后续改为指向站点链接）
nativeplugins/App 原生插件（当前仅 google-services.json）
keystone_public/发版归档：签名 / 安装包 / 截图 / 软著 / 账号资料（gitignore，不入库）

分包策略（重点） ​

分包原则（README 权威表述）：控制主包 2M 以内；分包与主包内容分离；功能页面全部拆进分包，主包只保留首页、功能菜单、我的。

当前 pages.json 实际结构（9 个分包 / 122 页，随业务增长从早期 4 分包拆分而来）：

分包 root页数内容
subPages/main_pages3navigation（功能菜单）、mine（我的）、notice（通知）——从主包迁入以瘦身
subPages/system7login / language / privacy / project×2 / web_view / version_debug
subPages/chart_page8图表统计页（qiun-data-charts 体系）
subPages/business/personnel_mgmt21人员：登记、考试、打卡、会议等
subPages/business/qual_mgmt41质量：拌合站、试验检测 19 个模块（最大分包）
subPages/business/safe_mgmt21安全：巡检、许可、视频监控（含 3 个播放器插件页）
subPages/business/machinery_mgmt16机械：龙门架、电力、运输、车辆、维保
subPages/business/env_mgmt2环境：智能电表 / 水表
subPages/business/progress_collab3进度：形象进度填报

主包 pages/ 仅 3 条注册：pages/index/index（首页）、components/pap-cascader/pap-cascader（级联弹层页面承载）、components/app-upgrade/index（#ifdef APP-PLUS 条件注册的升级弹窗）。

体积红线（如实记录的现状机制）

与 PC 端编译期裁剪不同，移动端页面全量打进分包，客户差异完全交给运行时权限与 prefix-rules。后果：包体积随业务只增不减，主包 2MB 是微信硬红线（当前靠 main_pages 迁包维持）；客户 A 的页面代码对客户 B 可见。分包体积监控已列入遗留项（缺口分析 §3.4）。

pages.json 结构说明 ​

  • pages：主包页面注册（首页必须第一条）；
  • subPackages：分包注册，root + pages[]；页面 path 写全如 business/qual_mgmt/cement_realtime_status/index；
  • 无 tabBar：底栏由自绘组件 pap-tabbar 实现（全局 navigationStyle: "custom"，导航栏也是自绘 pap-navbar）——原生 tabBar 配置不存在，别找错了；
  • globalStyle：custom 导航、标题「交付小程序」、背景 #F2F3F5；
  • easycom："^pap-(.*)": "@/components/pap-$1/pap-$1.vue"——pap 组件免 import 直接用；
  • optimization.subPackages：true（mp-weixin 与根级各一份），分包内组件按需打包。

页面三件套约定 ​

每个业务模块（如 subPages/business/personnel_mgmt/pers_reg/）统一：

  • index.vue：列表主页（统一命名，不叫 list.vue）；
  • detail.vue / edit.vue：详情与编辑（按需）；
  • lang.js：本模块 i18n 词条（并入 AppLang 聚合）；
  • api.js（可选）：本模块接口。

新增页面/模块的逐步操作见功能开发。
