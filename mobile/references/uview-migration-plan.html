uview-ui 全局加载改为局部加载迁移计划 ​

📋 项目概述 ​

目标：将 uview-ui 从全局加载改为局部加载，降低主包体积，提升应用性能

原则：

  1. 主包页面不使用任何 UI 组件库，全部替换为原生组件
  2. 每个分包创建独立的 components 目录
  3. 每个分包按需引入所需的 uview-ui 组件
  4. 暂不考虑分包间组件重复的问题

🔧 详细迁移计划 ​

一、主包页面重构（4个页面） ​

1.1 pages/index/index.vue ​

当前使用的 uview-ui 组件：

  • <u-grid> + <u-grid-item> → 替换为原生 CSS Grid 布局
  • <u-empty> → 替换为自定义空状态组件
  • <u-toast> → 替换为 uni.showToast() 或自定义 toast 组件

重构方案：

vue
<!-- 原代码 -->
<u-grid>
  <u-grid-item>
    <u-icon name="home"></u-icon>
  </u-grid-item>
</u-grid>

<!-- 重构后 -->
<view class="grid-container">
  <view class="grid-item">
    <uni-icons type="home"></uni-icons>
  </view>
</view>

<style>
.grid-container {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 20rpx;
}
</style>

1.2 pages/navigation/index.vue ​

当前使用的 uview-ui 组件：

  • <u-search> → 替换为原生搜索组件

重构方案：使用 uni-ui 的 uni-search-bar 或自定义搜索组件

1.3 pages/mine/index.vue ​

当前使用的 uview-ui 组件：

  • <u--image> → 替换为原生 <image> 或 <uni-icons>
  • <u-icon> → 替换为 <uni-icons>
  • <u-cell-group> + <u-cell> → 替换为原生 view 列表

重构方案：使用原生列表结构或 uni-ui 的 uni-list

1.4 pages/notice/index.vue ​

当前使用的 uview-ui 组件：

  • <u-tabs> → 替换为原生 tabs 或 uni-ui 的 uni-segmented-control
  • <u-swipe-action> + <u-swipe-action-item> → 替换为 uni-ui 的 uni-swipe-action

重构方案：优先使用 uni-ui 组件

🚀 实施步骤 ​

第一阶段：准备工作 ​

  1. 备份项目

    • 创建 git 分支：git checkout -b feature/uview-local-loading
    • 确保当前分支代码已提交

  2. 创建分包 components 目录结构

    bash
    # 为每个分包创建 components 目录

📝 注意事项 ​

  1. 组件路径引用

    • 复制组件后，需要更新页面中的引用路径
    • 例如：<pap-navbar /> → 改为绝对路径或在分包中引用

  2. 样式文件

    • uview-ui 的样式文件需要一并复制
    • 检查是否有全局样式依赖

  3. 组件依赖

    • 某些 uview-ui 组件可能依赖其他组件
    • 复制时需要确保依赖完整

  4. 测试策略

    • 每完成一个分包，立即测试
    • 发现问题及时修复
    • 建议使用真机测试

  5. 回滚方案

    • 每个阶段完成后提交代码
    • 发现问题可快速回滚到上一个稳定版本
