pap-button 按钮能力与权限说明 ​

目标 ​

  • 统一说明 components/pap-button/pap-button.vue 的当前能力。
  • 定稿按钮权限的最终使用方式。
  • 删除与当前实现不一致的旧说明，避免页面继续按旧模型接入。

组件定位 ​

  • pap-button 是项目统一按钮出口。
  • 页面层新增业务按钮优先使用 pap-button。
  • pap-button 同时承接：
    • 基础按钮能力
    • 权限控制能力
    • 统一点击行为

基础能力 ​

基础 props ​

  • type
    • 可选值：default | primary | success | warning | danger
    • 默认值：default
  • size
    • 可选值：mini | small | medium | large
    • 默认值：medium
  • block
    • 是否块级按钮
  • disabled
    • 是否业务禁用
  • loading
    • 是否加载中
  • outline
    • 是否使用描边风格
  • text
    • 按钮文字
  • customClass
    • 自定义类名
  • customStyle
    • 自定义容器样式，支持 String | Object
  • openType
    • 小程序原生按钮能力透传

事件 ​

  • click
    • 普通点击事件
  • getphonenumber
    • 小程序获取手机号事件

权限能力 ​

最终权限模型 ​

  • permission
    • 主入口
    • 传入权限码，例如 vehRegPerm.add
  • permissionMode
    • 无权限时的表现模式
    • 可选值：hide | disable | message
    • 默认值：disable
  • permissionMessage
    • 无权限提示文案
    • 默认值：暂无权限执行该操作
  • permissionGranted
    • 复杂场景兜底入口
    • 仅在页面需要自己组合权限结果时使用

权限模式说明 ​

disable ​

  • 默认模式
  • 无权限时按钮显示，但不可点击
  • 适合大多数业务按钮

hide ​

  • 无权限时按钮不渲染
  • 适合高风险或不希望暴露给无权限用户的动作

message ​

  • 无权限时按钮显示
  • 点击后提示 permissionMessage
  • 不执行业务动作

语义边界 ​

disabled 的职责 ​

  • disabled 只表达业务禁用
  • 例如：
    • 表单未填写完成
    • 数据未选择
    • 单据状态不允许
    • 正在提交

权限能力的职责 ​

  • permission / permissionGranted / permissionMode 只表达权限不可操作
  • 不要把 !hasPermission(...) 直接混入 disabled

并存时的处理规则 ​

  • 权限先决定按钮的暴露方式
  • 业务再决定按钮是否因为业务条件不可点击
  • 页面不要同时向用户暴露“权限不足”和“业务不可操作”两套原因

推荐用法 ​

1. 常规权限按钮 ​

vue
<pap-button
  :permission="vehRegPerm.add"
  type="primary"
  text="新增车辆登记"
  @click="pageJump('report')"
/>

说明：

  • 最常见写法
  • 使用 permission 作为主入口
  • 不需要主动设置 permissionMode，默认就是 disable

2. 需要隐藏的权限按钮 ​

vue
<pap-button
  :permission="vehRegPerm.edit"
  permission-mode="hide"
  size="small"
  text="编辑"
  @click="handleEdit(row)"
/>

说明：

  • 用于不希望无权限用户看到按钮的场景

3. 需要提示的权限按钮 ​

vue
<pap-button
  :permission="vehRegPerm.delete"
  permission-mode="message"
  :permission-message="t('暂无删除车辆权限')"
  type="danger"
  text="删除"
  @click="handleDelete(row)"
/>

说明：

  • 用于需要给无权限用户明确提示的场景

4. 复杂权限场景 ​

vue
<pap-button
  :permission-granted="isAdmin || hasPermission(vehRegPerm.add, menuGroupId)"
  text="特殊按钮"
  @click="handleSubmit"
/>

说明：

  • 仅在页面需要自行组合复杂权限条件时使用
  • 简单场景优先使用 permission

5. 业务禁用场景 ​

vue
<pap-button
  :permission="vehRegPerm.add"
  :disabled="formInvalid || submitting"
  text="提交"
  @click="handleSubmit"
/>

说明：

  • 有权限，但因为业务条件不满足暂时不可操作
  • disabled 不替代权限判断

6. 共用页面动态权限场景 ​

vue
<template>
  <!-- 模板中使用计算属性 -->
  <pap-button
    :permission="currentPerm.edit"
    text="编辑"
    @click="handleEdit"
  />
  <pap-button
    :permission="currentPerm.delete"
    text="删除"
    @click="handleDelete"
  />
</template>

<script>
import { hazardInspPlanPerm, comInspPlanPerm } from '@/constants/permissions';

export default {
  data() {
    return {
      currentScene: 'hazard', // 或 'comprehensive'
      hazardInspPlanPerm,
      comInspPlanPerm,
    }
  },
  computed: {
    // 根据业务场景动态返回权限对象
    currentPerm() {
      return this.currentScene === 'comprehensive'
        ? this.comInspPlanPerm
        : this.hazardInspPlanPerm;
    }
  }
}
</script>

说明：

  • 当页面组件被多个业务场景共用时，使用计算属性实现动态权限切换
  • 将权限选择逻辑集中在计算属性中，便于维护
  • 模板中使用统一的 currentPerm，代码更简洁
  • 避免在模板中写冗长的三元运算符条件判断

不推荐用法 ​

1. 页面散落权限判断 ​

vue
<pap-button
  v-if="hasPermission(vehRegPerm.add)"
  text="新增"
/>

问题：

  • 权限逻辑散落在页面
  • 后续无法统一切换为 disable 或 message

2. 把权限混进 disabled ​

vue
<pap-button
  :disabled="!hasPermission(vehRegPerm.add) || formInvalid"
  text="提交"
/>

问题：

  • 权限语义和业务语义混在一起
  • 无法区分是“没权限”还是“业务条件不满足”

3. 使用过时的运行时主入口 ​

vue
<pap-button permission-code="vehicle:add" />

问题：

  • 当前 pap-button 运行时主入口不是 permissionCode
  • 当前最终模型以 permission 为主

权限配套约定 ​

权限常量 ​

  • 统一放在 constants/permissions.js
  • 推荐通过 definePermission() 生成模块权限对象

例如：

js
export const vehRegPerm = definePermission('vehicle')

权限缓存与判断 ​

  • 统一放在 utils/permissions.js
  • 当前能力包括：
    • 菜单组权限拉取
    • 24 小时本地缓存
    • hasPermission() 判断

当前结论 ​

  • permission 是 pap-button 的权限主入口。
  • permissionMode 默认值固定为 disable。
  • permissionMessage 有统一默认文案，只有特殊业务才需要覆盖。
  • permissionGranted 只用于复杂场景，不作为普通页面默认写法。
  • disabled 只表示业务禁用，不表示权限禁用。
