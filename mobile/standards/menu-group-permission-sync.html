uni-app 菜单组按钮权限同步方案 ​

目标 ​

  • 明确项目中按钮权限的同步边界，避免后端权限码更新后前端长时间停留在旧状态。
  • 将按钮权限同步收口到菜单组上下文，而不是分散到每个业务页面。
  • 保留 pap-button 的权限兜底能力，保证边缘场景下按钮仍能正确判权。

设计前提 ​

  • 当前按钮权限本质上属于 menuGroupId 上下文，不属于某一个具体页面。
  • 同一菜单组下的多个页面应共享同一份按钮权限缓存。
  • 后端接口返回的是菜单组维度的权限集合，前端只负责缓存、刷新和消费。

推荐方案 ​

主方案：菜单上下文统一刷新 ​

  • 以菜单分类组件作为主刷新入口。
  • 在以下时机刷新当前 menuGroupId 的按钮权限：
    • 菜单分类初始化完成后
    • 切换菜单分类后
    • 点击某个功能页面并准备跳转前
  • 统一入口刷新时，使用强制刷新策略拉取后端最新权限并覆盖本地缓存。

兜底方案：pap-button 按需补同步 ​

  • pap-button 在传入 permission 时，仍保留按需判权能力。
  • 当页面没有主动传 permissionGranted 时，组件内部可通过当前菜单组缓存执行权限判断。
  • 当菜单组权限缓存更新后，pap-button 通过全局事件重新执行判权，避免按钮停留在旧状态。

为什么不推荐页面层普遍强刷 ​

  • 权限属于菜单组上下文，不是页面私有状态。
  • 如果每个页面都在 onLoad 中强制刷新，容易产生重复请求和维护分散问题。
  • 页面越多，越容易出现部分页面忘记刷新、刷新策略不一致的问题。

页面层原则 ​

  • 默认情况下，业务页面不自行强制刷新按钮权限。
  • 页面只负责传入 permission 或 permissionGranted，不直接管理菜单组权限缓存。
  • 只有极少数脱离菜单上下文的直达页，才允许增加一次页面级兜底刷新。

典型链路 ​

场景 1：正常从菜单进入业务页 ​

  1. 菜单分类组件初始化当前 menuGroupId
  2. 菜单分类组件刷新该菜单组按钮权限
  3. 权限缓存写入完成后广播更新事件
  4. 页面中的 pap-button 消费最新缓存并完成判权

场景 2：切换菜单分类 ​

  1. 用户切换左侧菜单分类
  2. 菜单分类组件刷新新分类对应的按钮权限
  3. 权限缓存覆盖旧值并广播更新事件
  4. 当前页面或后续进入页面的按钮都使用新权限结果

场景 3：点击功能页面进入业务页 ​

  1. 用户点击某个功能页面入口
  2. 跳转前先刷新当前 menuGroupId 的按钮权限
  3. 本地缓存覆盖为最新权限集合
  4. 进入页面后 pap-button 直接消费最新缓存

场景 4：后端修改权限码 ​

  1. 后端将权限码从旧值改为新值
  2. 前端下一次触发菜单上下文刷新时重新拉取权限列表
  3. 本地菜单组缓存被新权限集合覆盖
  4. pap-button 收到缓存更新事件后重新判权

缓存策略 ​

  • 菜单组按钮权限按 menuGroupId 单独缓存。
  • 缓存过期并不等于自动刷新。
  • 只有再次触发权限读取或显式刷新时，前端才会感知缓存失效并重新请求后端。
  • 这也是为什么仅依赖短期缓存过期可以止血，但不适合作为长期主方案。

推荐写法 ​

vue
<pap-button
  :permission="vehRegPerm.add"
  text="新增车辆登记"
  @click="handleAdd"
/>
  • 页面只传业务所需权限码。
  • 权限缓存同步由菜单上下文统一负责。
  • 组件内部只负责展示裁决和兜底判权。

不推荐写法 ​

js
onLoad() {
  ensureMenuGroupPerms(getCurrentMenuGroupId(), { forceRefresh: true })
}
  • 不建议把这类强制刷新散落到每个业务页面。
  • 除非该页面明确属于脱离菜单上下文的直达页，否则应优先复用统一刷新入口。

与按钮禁用语义的关系 ​

  • disabled 只表达业务禁用，不表达权限禁用。
  • 权限仍统一走 permission / permissionGranted / permissionMode。
  • 当后端权限变化时，刷新的是权限上下文，不是业务禁用状态。

关键实现位置 ​

  • utils/permissions.js
    • 管理菜单组权限缓存、主动刷新、事件广播和调试开关
  • subPages/main_pages/components/pap-category/pap-category.vue
    • 作为菜单上下文的主刷新入口
  • components/pap-button/pap-button.vue
    • 负责按钮权限裁决和缓存更新后的重判

验证建议 ​

  • 修改后端某个按钮权限码后，从菜单重新进入对应业务模块。
  • 确认菜单组权限接口返回的是最新权限集合。
  • 确认本地 menuGroupPerms:<menuGroupId> 缓存被覆盖。
  • 确认页面上 pap-button 的禁用、隐藏或提示行为随新权限即时变化。
