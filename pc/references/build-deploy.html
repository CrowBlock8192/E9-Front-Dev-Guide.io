PC 端 · 构建与部署 ​

基于 keystone-deliver-ui 的 Dockerfile 与 nginx/conf/nginx.conf（2026-09-16 核对）。

构建流程 ​

sh
pnpm start      # 交互选择：业务视图 → 模式（production 等）→ 「打包构建」

views-switcher 将 VITE_BUILD_VIEWS 写入 .env.<mode> 后自动执行 vite build --mode <mode>，产物输出到 dist/。

构建前必查

  • 业务视图选择是否正确——选漏了客户要的视图，产物里就没有该业务；
  • pnpm switch:api 是否指向目标客户后端（写入各 .env.* 的 VITE_APP_BASE_API）；
  • 不同客户 / 不同模式不能共用一次构建产物，每客户单独构建打包。

Dockerfile ​

镜像内不做构建，只装产物：

dockerfile
FROM registry.cn-hangzhou.aliyuncs.com/yangxing1993/nginx:202406
VOLUME /opt/epim
WORKDIR /opt/epim
COPY ./nginx/conf/nginx.conf /etc/nginx/nginx.conf
COPY ./nginx/TnonuTWyPN.txt /opt/epim/TnonuTWyPN.txt   # 域名验证文件（标品独有）
COPY ./dist /opt/epim

nginx 目录说明 ​

nginx
listen 80;
root /opt/epim;
try_files $uri $uri/ /index.html;      # SPA 兜底
gzip on;  gzip_comp_level 6;           # js/css/json/svg 压缩
client_max_body_size 100m;             # 上传上限
error_page 500 502 503 504 /50x.html;

静态站点部署在容器 /opt/epim，刷新深链路由 try_files 回退 index.html（应用路由为 hash 模式，/#/login）。

各客户产物差异 ​

差异点由什么决定
包含哪些业务页面VITE_BUILD_VIEWS（pnpm start 选择）
请求指向VITE_APP_BASE_API（pnpm switch:api 选择）
标题 / logo.env 的 VITE_APP_TITLE / VITE_APP_LOGO（副本仓库各自维护）

部署步骤速查 ​

  1. 本地（或 CI 机）pnpm start 按客户选择视图与 production 模式打包；
  2. 构建镜像（或直接把 dist/ 与 nginx/ 交给运维），推送镜像仓库；
  3. 客户环境拉起容器（/opt/epim 挂载站点），确认 nginx 配置与域名验证文件就位。
