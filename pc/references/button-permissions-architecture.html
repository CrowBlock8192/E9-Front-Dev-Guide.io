Keystone 2.0 按钮权限使用指南(原理与详细设计) ​

日常开发请看实操规范:button-permission-guide.md(接入步骤/写法/场景/排查)。本文侧重体系原理、指令行为设计与完整示例。

概述 ​

本文档详细说明 Keystone 2.0 项目中按钮权限系统的使用方法，包括配置方式、使用示例和最佳实践。权限系统采用三层控制：

  1. 全局开关 - 控制所有页面的默认权限状态
  2. 页面级配置(可选) - 单独覆盖某个页面的开关，未配置的页面跟随全局
  3. 权限常量 - 定义具体的按钮权限标识

体系原理(数据流) ​

后端(角色-菜单权限接口 getRoleMenuPermsApi)
   → permission store 的 permissions 数组(持久化于 localStorage 'permission-store')
   → usePermission().hasPermission(标识)   ← src/hooks/permission.js
   → v-permission 指令                      ← src/directives/permission.js
   → 按钮禁用/隐藏 + 点击拦截

权限标识格式:{模块}:{资源}:{操作},如 cfg:procTpl:deploy。

放行规则(重要) ​

hasPermission 会解析权限标识的前两段作为页面 key(如 cfg:procTpl:deploy → 'cfg:procTpl')，查 pagePermissions 配置：

  • 该页面被配置为 true(或未配置但全局开关为 true)→ 正常比对后端下发的权限列表；
  • 该页面被配置为 false(或未配置且全局开关为 false)→ 直接返回 true 放行，按钮可用，不比对权限。

即:pagePermissions 是可选的覆盖项，不是必填登记表——只有需要与全局开关不同的页面才需要条目，未配置的页面一律跟随 globalPermissionEnabled。两种典型用法：

  • 全局 true(当前默认)→ 所有页面默认校验，pagePermissions 用于豁免个别页面(设 false)；
  • 全局 false(如开发调试)→ 所有页面默认放行，pagePermissions 用于对个别页面单独启用(设 true)。

1. 基本配置 ​

// 单个页面的权限配置（覆盖全局设置）

  // 流程模板页面 - 单独启用

  // 人员管理页面 - 单独启用（当前注释掉）
  // 'pers:pers_reg': true,

javascript
// src/constants/permissions.js

// 流程模板权限

    <button v-permission="cfgProcTplPerm.oc">OC操作</button>
    <!-- 使用字符串权限 -->

// Vue 3 <script setup> 语法，权限常量直接可用
</script>

数组权限说明 ​

工作原理 ​

v-permission 指令支持数组形式的权限，使用 Array.some() 进行判断：

javascript
// 数组权限：任意一个满足即通过（OR 逻辑）
v-permission="[perm1, perm2]"
// 等价于：hasPermission(perm1) || hasPermission(perm2)

使用场景 ​

适用场景：

  • 按钮在多个不同功能中使用，但功能相同
  • 例如：管理员或超级管理员都可以删除
vue
<!-- ✅ 正确：管理员或超级管理员都可以删除 -->
<button v-permission="['admin', 'superAdmin']">删除</button>

不适用场景：

  • 通用页面根据路由区分不同功能
  • 需要精确控制每个功能的权限
vue
<!-- ❌ 不推荐：通用页面使用数组权限 -->
<button v-permission="[safeHazardInspPlanPerm.add, safeComInspPlanPerm.add]">
  新建
</button>

问题：使用数组权限时，只要有一个权限满足就通过，无法精确控制。

最佳实践 ​

对于通用页面，推荐使用动态权限计算属性（参见"场景1：通用页面动态权限"），避免使用数组权限。

权限控制模式 ​

模式一：全局禁用（开发测试） ​

javascript
// 全局禁用权限控制，所有按钮都可用
setGlobalPermissionEnabled(false);

效果：所有按钮都显示且可用，不进行权限校验

模式二：全局启用（生产环境） ​

javascript
// 全局启用权限控制
setGlobalPermissionEnabled(true);

效果：所有页面的按钮都按用户权限正常显示/隐藏

模式三：选择性覆盖(按需豁免或单独启用) ​

pagePermissions / setPagePermissionEnabled 的定位是覆盖全局的可选配置，不是逐页必填登记：

javascript
// 全局开启时(当前默认)：豁免个别页面(如调试中的页面)
setPagePermissionEnabled('cfg:procTpl', false);

// 全局关闭时(开发调试)：仅对关键页面单独启用
setPagePermissionEnabled('pers:pers_reg', true);

// 或者批量设置
batchSetPagePermissions({
  'cfg:procTpl': false,
  'pers:pers_reg': true,
});

效果：被配置的页面按配置执行，未配置的页面一律跟随全局开关

v-permission 指令行为设计 ​

指令实现位于 src/directives/permission.js，要点：

1. 无权限时的三种模式(mode) ​

mode行为
disable-with-tip(默认)加 perm-disabled class；button/arco-btn 设 disabled；title 提示"暂无权限"(可通过 tipContent 自定义)
disable同上但不加提示
其他任意值直接 display: none 隐藏

对象传值格式:{ perm: 权限标识, mode: 'disable', tip: true/false, tipContent: '自定义提示' }

2. 点击拦截 ​

指令在捕获阶段注册 click 监听，禁用态(perm-disabled)下 preventDefault + stopImmediatePropagation，保证即使某些组件不响应 disabled 属性，点击也不会触发业务 handler。

3. 响应式更新 ​

指令内部用 watchEffect 包裹权限判断，permission store 的权限列表变化(如重新获取权限、切换角色)后，按钮状态自动更新，无需刷新页面。unmounted 时自动停止监听并解绑拦截。

4. 非法传值的防御式报错 ​

传值为 undefined/null/空字符串时，指令会抛出详细诊断错误，包含元素信息、按钮文本、可能原因(常见:cfgProcTplPerm.deploy 属性未在 definePermission 中定义、常量未导入)和正确用法示例。这是刻意的开发期防御，出现即必须修复，不允许带错上线。

5. 与 :disabled 冲突的根源(仅 a-button 类元素) ​

指令权限放行时会执行 removeAttribute('disabled') 清理状态，与 Vue 响应式 :disabled 绑定相互覆盖，导致"先禁用又启用"。因此规范要求权限与数据状态合并进同一个 computed(见实操规范场景 5.2 场景 A)。

注意组件差异：冲突只发生在把 disabled 渲染为原生属性的元素上——a-button 内部是 <button :disabled>(原生属性)。而 a-link 的禁用态由 arco-link-disabled class + 组件内部点击拦截实现，指令对 arco-link 也只设置 aria-disabled，双方都不碰 disabled 属性，因此 v-permission 与 :disabled 在 a-link 上可以同用(见实操规范场景 5.2 场景 B)。

常见场景判断 ​

场景1：CRUD操作 ​

  • ✅ 标准操作：add, edit, delete, detail
  • 📝 说明：这些是最常见的操作，在几乎所有管理页面都会使用

场景2：数据导入导出 ​

  • ✅ 标准操作：import, export
  • 📝 说明：如果多个页面都有导入导出功能，使用标准操作

场景3：业务流程操作 ​

  • ⚠️ 需要判断：deploy, approve, reject, submit
  • 📝 说明：检查是否在多个页面使用，如果是则考虑加入标准操作

场景4：页面特有功能 ​

  • ✅ 自定义操作：setSynt, readFlow, maintenance
  • 📝 说明：仅在一个页面中使用的特殊功能

最佳实践 ​

1. 优先使用标准操作 ​

javascript
// ✅ 推荐：使用标准操作
export const productPerm = definePermission('catalog:product');
// 自动生成所有标准操作权限

2. 谨慎添加自定义操作 ​

javascript
// ✅ 推荐：只有真正特殊的功能才使用自定义操作
export const specialPerm = definePermission('module:resource', {
  customAction: 'custom'  // 仅当此操作确实特殊时使用
});

3. 保持一致性 ​

javascript
// ✅ 推荐：相似功能使用相同操作名
export const userPerm = definePermission('sys:user', {
  activate: 'activate',
  deactivate: 'deactivate'
});

export const rolePerm = definePermission('sys:role', {
  activate: 'activate',    // 与userPerm保持一致
  deactivate: 'deactivate' // 与userPerm保持一致
});

故障排除 ​

问题1：权限未生效 ​

javascript
// ❌ 错误：使用了不存在的操作
export const perm = definePermission('module:resource', {
  nonStandardOp: 'nonStandard'  // 拼写错误或不存在
});

// ✅ 正确：使用标准操作或正确定义的自定义操作
export const perm = definePermission('module:resource', {
  customOp: 'customOp'  // 确保后端支持此权限
});

问题2：权限过多 ​

javascript
// ❌ 不推荐：过度定义自定义操作
export const perm = definePermission('module:resource', {
  add: 'add',      // 已经是标准操作，无需重复定义
  edit: 'edit',    // 已经是标准操作，无需重复定义
  delete: 'delete', // 已经是标准操作，无需重复定义
  custom: 'custom'
});

// ✅ 推荐：只定义真正的自定义操作
export const perm = definePermission('module:resource', {
  custom: 'custom'  // 只定义非标准操作
});

常见使用场景 ​

场景1：通用页面动态权限（推荐） ​

当一个页面组件根据路由参数服务于不同的业务场景时，需要使用动态权限控制。

问题场景：

vue
<!-- ❌ 不推荐：使用数组权限，逻辑为"任意一个满足即通过" -->
<template>
  <button v-permission="[safeHazardInspPlanPerm.add, safeComInspPlanPerm.add]">
    新建
  </button>
</template>

问题：v-permission 对数组使用 Array.some() 判断，只要有一个权限满足就通过。这会导致：

  • 隐患排查页面（只需要 safeHazardInspPlanPerm.add）因有综合巡检权限而显示按钮
  • 综合巡检页面（只需要 safeComInspPlanPerm.add）因有隐患排查权限而显示按钮

解决方案：使用计算属性根据路由动态返回所需权限

vue
<template>
  <!-- ✅ 推荐：使用动态权限 -->
  <button v-permission="addPermission">新建</button>
  <button v-permission="editPermission">编辑</button>
  <button v-permission="deletePermission">删除</button>
  <button v-permission="exportPermission">导出</button>
</template>

<script setup>
import { ref, computed } from 'vue';
import { useRoute } from 'vue-router';
import { safeHazardInspPlanPerm, safeComInspPlanPerm } from '@/constants/permissions';

const route = useRoute();

// 根据路由类型动态返回对应的权限
// 隐患排查：safe:hazardInspPlan，综合巡检：safe:comInspPlan
const inspectionType = computed(() => route.query.type);

const permissionMapping = {
  hazard: safeHazardInspPlanPerm,
  comprehensive: safeComInspPlanPerm,
};

const currentPermissions = computed(() => {
  const type = inspectionType.value || 'hazard'; // 默认为隐患排查
  return permissionMapping[type] || safeHazardInspPlanPerm;
});

// 各操作权限
const addPermission = computed(() => currentPermissions.value.add);
const editPermission = computed(() => currentPermissions.value.edit);
const deletePermission = computed(() => currentPermissions.value.delete);
const exportPermission = computed(() => currentPermissions.value.export);
const approvalPermission = computed(() => currentPermissions.value.approval);
</script>

适用场景：

  • 通过 route.query.type 区分不同业务类型
  • 通过 route.query.pageType 区分不同页面模式
  • 一个组件服务于多个不同的功能模块

示例路由：

  • /inspection_plan?type=hazard - 隐患排查巡检计划
  • /inspection_plan?type=comprehensive - 综合巡检巡检计划
  • /inspection_plan?pageType=mine&type=hazard - 我的隐患排查巡检记录

vue

场景4：权限与数据状态结合禁用（推荐） ​

问题场景：

vue
<!-- ❌ 不推荐：v-permission 和 :disabled 同时使用会产生冲突 -->
<template>
  <button
    @click="handleExport"
    :disabled="!tableData.length"
    v-permission="qualTunnelDailyRptPerm.export"
  >
    导出
  </button>
</template>

问题根源：

  • v-permission 指令在权限满足时会 removeAttribute('disabled')
  • 你的 :disabled="!tableData.length" 会根据数据状态设置 disabled
  • 当两者同时使用时：
    1. 如果 tableData.length > 0，Vue 设置 disabled=false
    2. 但 v-permission 检测权限不足时设置 disabled=true
    3. 最后 Vue 响应式更新又因为数据存在而设置 disabled=false
    4. 结果就是"先禁用一下，然后又启用"

预期行为：

  • 没有数据时，按钮禁用
  • 没有权限时，按钮也要禁用
  • 两者任何一个条件不满足都应该禁用

解决方案：使用 computed 属性同时检查权限和数据状态

vue
<template>
  <!-- ✅ 推荐：使用 computed 属性结合权限和数据状态 -->
  <button
    @click="handleExport"
    :disabled="exportDisabled"
  >
    导出
  </button>
</template>

<script setup>
import { ref, computed } from 'vue';
import { usePermission } from '@/hooks/permission';
import { qualTunnelDailyRptPerm } from '@/constants/permissions';

const { hasPermission } = usePermission();

const tableData = ref([]);

// 导出按钮的禁用状态：需要同时有数据且有权限
const exportDisabled = computed(() => {
  const hasNoData = !tableData.value.length;
  const hasNoPermission = !hasPermission(qualTunnelDailyRptPerm.export);
  return hasNoData || hasNoPermission; // 任意一个不满足就禁用
});
</script>

适用场景：

  • 导出按钮（需要数据 + 权限）
  • 批量操作按钮（需要选中项 + 权限）
  • 提交按钮（需要表单有效 + 权限）
  • 任何需要同时满足多个条件才能操作的场景

优势：

  • ✅ 避免了 v-permission 和 :disabled 的冲突
  • ✅ 逻辑清晰，易于维护
  • ✅ 可以灵活组合多个条件
  • ✅ 权限检查响应式更新

错误处理 ​

1. 权限未定义错误 ​

Error: 权限配置错误: 在 <button> 上发现无效的权限配置
原因: 权限值是 undefined

解决方案：

  1. 检查权限常量是否正确定义
  2. 确保权限常量已正确导入
  3. 验证权限属性是否存在

2. 权限格式错误 ​

Error: 权限值格式不正确: "undefined"

解决方案：

  1. 避免使用未定义的变量
  2. 使用正确的权限常量
  3. 检查权限标识格式
