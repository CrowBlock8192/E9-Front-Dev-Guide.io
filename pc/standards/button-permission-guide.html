按钮权限实操规范 ​

机制原理、指令行为设计、数据流等说明见 button-permissions-architecture.md。本文只讲怎么用、怎么写才规范。

一、新页面接入(标准 4 步) ​

以质量管理新页面 qual:newFeat 为例：

Step 1：定义权限常量 —— src/constants/permissions.js 找到质量管理分区添加：

js
// 新功能管理权限
export const qualNewFeatPerm = definePermission('qual:newFeat');
// 标准操作自动生成: add/edit/delete/detail/export/import 等，无需手写

Step 2：确认页面权限开关 —— 权限校验默认全局开启(globalPermissionEnabled = true)。pagePermissions 是可选的页面级覆盖项，不需要逐页登记，未配置的页面自动跟随全局开关。仅当该页面需要与全局不同的开关(如调试期单独豁免)时才在 src/constants/pagePermissions.js 中添加：

js
export const pagePermissions = {
	'qual:newFeat': false, // 示例：单独关闭该页面校验(一般无需添加)
};

Step 3：按钮挂指令：

vue
<template>
	<a-button v-permission="qualNewFeatPerm.add" type="primary" @click="handleAdd">新增</a-button>
	<a-button v-permission="qualNewFeatPerm.edit" @click="handleEdit(row)">编辑</a-button>
	<a-button v-permission="qualNewFeatPerm.delete" @click="handleDelete(row)">删除</a-button>
</template>

<script setup>
import { qualNewFeatPerm } from '@/constants/permissions';
</script>

Step 4：后端配置 + 双角色自测：

  1. 在菜单权限管理中为相应角色勾选 qual:newFeat:add 等标识(前端只做匹配，权限数据全在后端)；
  2. 分别用有/无权限的账号登录自测：无权限时按钮呈禁用态、悬停提示"暂无权限"、点击无任何响应。

二、权限常量定义规范 ​

js
// ✅ 标准：只定义资源路径
export const qualNewFeatPerm = definePermission('qual:newFeat');

// ✅ 单页面特殊操作才传自定义
export const cfgProcTplPerm = definePermission('cfg:procTpl', {
	deploy: 'deploy',
	oc: 'oc',
});

// ❌ 标准操作不要重复定义
export const badPerm = definePermission('x:y', {
	add: 'add', // 已自动生成
});

规则：

#规则
1常量名 {模块}{资源}Perm，如 qualNewFeatPerm、cfgProcTplPerm
2资源路径 {模块}:{资源}，模块前缀用业务域缩写(qual/cfg/mach/pers/safe/env/mat…)
3优先用标准操作；只有单页面的特殊功能才定义自定义操作
4同类功能跨页面使用相同操作名(如统一 enable/disable)
5多个页面出现的自定义操作应提升为标准操作(改 permissionHelper.js)

三、标准操作清单 ​

直接可用，无需定义：

分组操作
基础add edit delete detail export import
多页面通用disable batchDelete batchLink config record updateState approval

四、按钮写法规范 ​

4.1 推荐写法 ​

vue
<template>
	<!-- ① 权限常量(默认推荐) -->
	<a-button v-permission="qualNewFeatPerm.add">新增</a-button>

	<!-- ② 对象：需要调整禁用模式/提示时 -->
	<a-button v-permission="{ perm: cfgProcTplPerm.oc, mode: 'disable', tip: false }">启用</a-button>

	<!-- ③ 字符串(仅临时/一次性的简单场景) -->
	<a-button v-permission="'cfg:procTpl:deploy'">部署</a-button>

	<!-- ④ 数组：任意满足即通过，仅限真正"或"语义(如 admin 或 superAdmin 都可操作) -->
	<a-button v-permission="['admin', 'superAdmin']">删除</a-button>
</template>

mode 取值：disable-with-tip(默认，禁用+悬停提示) / disable(仅禁用) / 其他任意值(直接隐藏)。

4.2 禁止事项 ​

#禁止原因与替代
1v-permission 与 :disabled 同用于 a-button指令直接写/删原生 disabled 属性，与 Vue 绑定互相覆盖 → 改用 5.2 场景 A 的合并写法(a-link 的禁用由 class 实现，不受影响，可同用，见 5.2 场景 B)
2通用页面用数组权限区分业务数组是 OR 语义，A 业务会因 B 业务权限越权显示 → 改用 5.1 的动态映射
3手写字符串标识替代常量拼写错误无法在编译期发现，统一走常量
4忽略控制台"权限配置错误"报错undefined/null/空串标识必须修复后才能提交
5误把 pagePermissions 当必填逐页登记它是可选覆盖项：未配置的页面跟随全局开关，仅个别页面需要独立开关时才配置

4.3 script 中判断权限 ​

js
import { usePermission } from '@/hooks/permission';
import { qualNewFeatPerm } from '@/constants/permissions';

const { hasPermission } = usePermission();
hasPermission(qualNewFeatPerm.export); // boolean

五、典型场景实操 ​

5.1 通用页面按业务动态映射权限 ​

一个组件通过 route.query 服务多个业务时：

js
const permissionMapping = {
	hazard: safeHazardInspPlanPerm,
	comprehensive: safeComInspPlanPerm,
};
const currentPermissions = computed(() => permissionMapping[route.query.type] || safeHazardInspPlanPerm);
const addPermission = computed(() => currentPermissions.value.add);
const exportPermission = computed(() => currentPermissions.value.export);
vue
<a-button v-permission="addPermission">新建</a-button>
<a-button v-permission="exportPermission">导出</a-button>

5.2 权限 + 数据状态共同控制 ​

分两种情况：a-button 必须合并进一个 :disabled；a-link 可以直接同用。

场景 A：a-button —— 必须合并，禁止同用 ​

改造前(错误示范，线上真实代码)：

vue
<a-button v-permission="safeWorkPermitMyPerm.approval" @click="handleApproval(false)" :disabled="firstApprovalDisabled">
	{{ $t('发起审批') }}
</a-button>

问题：权限放行时指令会 removeAttribute('disabled')，把 Vue 初始绑定的禁用状态直接清掉(按钮在数据不该可点时可点)；权限不足时指令 setAttribute('disabled') 又会被 Vue 后续 patch 冲掉。

改造后：把权限并入 :disabled，去掉 v-permission：

js
import { usePermission } from '@/hooks/permission';
import { safeWorkPermitMyPerm } from '@/constants/permissions';

const { hasPermission } = usePermission();
const approvalDisabled = computed(
	() => firstApprovalDisabled.value || !hasPermission(safeWorkPermitMyPerm.approval)
);
const extensionApprovalDisabled = computed(
	() => secondApprovalDisabled.value || !hasPermission(safeWorkPermitMyPerm.extensionApproval)
);
vue
<a-button :disabled="approvalDisabled" @click="handleApproval(false)">
	{{ $t('发起审批') }}
	<a-tooltip :content="$t('审批中和已通过申请的许可证不可再发起审批单')">
		<icon-info-circle class="ml-2" />
	</a-tooltip>
</a-button>
<a-button :disabled="extensionApprovalDisabled" @click="handleApproval(true)">
	{{ $t('发起延期审批') }}
	<a-tooltip :content="$t('生效中和生效未超过3小时的许可证可发起延期审批单')">
		<icon-info-circle class="ml-2" />
	</a-tooltip>
</a-button>

同页面级按钮同理："有数据且有权限"才可点的导出/批量操作： const exportDisabled = computed(() => !tableData.value.length || !hasPermission(qualNewFeatPerm.export));

场景 B：a-link —— 可直接同用(表格操作列推荐写法) ​

vue
<a-link
	v-permission="qualBridgeCraneAlarmRecordPerm.approval"
	status="normal"
	:disabled="record.disabled"
	@click="handleApproval(record)"
>
	{{ $t('发起审批') }}
</a-link>

为何安全：a-link 的禁用态由 arco-link-disabled class + 组件内部点击拦截实现，不渲染原生 disabled 属性；指令对 arco-link 也只加 perm-disabled class 和 aria-disabled，不碰 disabled 属性 → 两者互不干扰：

  • 仅无权限 → 链接半透明、悬停提示"暂无权限"、点击被拦截；
  • 仅 record.disabled → 链接呈 Arco 标准禁用样式；
  • 两者同时 → 双重禁用。

组件对照速记 ​

组件disabled 实现v-permission + :disabled 同用
a-button原生 disabled 属性❌ 冲突，必须合并(场景 A)
a-linkclass + 组件内拦截✅ 可同用(场景 B)

5.3 行级业务条件 + 权限叠加 ​

v-if 管业务条件，v-permission 管权限，两者职责分离、可同用：

vue
<a-button v-if="record.status === 'draft'" v-permission="qualNewFeatPerm.edit">编辑</a-button>
<a-button v-if="record.status === 'draft'" v-permission="qualNewFeatPerm.delete">删除</a-button>

六、提交前自查清单 ​

  • [ ] 权限常量已定义且只用了标准操作(自定义操作确为单页面)？
  • [ ] 该页面权限校验处于开启状态(全局开关为 true，且未被 pagePermissions 单独设为 false)？
  • [ ] 所有面向用户的操作按钮都挂了 v-permission？
  • [ ] a-button 上没有 v-permission 与 :disabled 同用(a-link 可同用)？
  • [ ] 通用页面没有用数组权限区分业务？
  • [ ] 控制台无"权限配置错误"报错？
  • [ ] 无权限角色自测：按钮禁用、悬停提示、点击无响应？

七、问题速查 ​

现象处理
按钮无权限也不禁用查开关链路:globalPermissionEnabled 是否为 false，或该页面 key(标识前两段)在 pagePermissions 中被单独设为 false
控制台报"权限值是 undefined"常量未导入，或访问了未定义的属性(拼错操作名)
a-button 初始禁用态丢失或"先禁用又启用"v-permission 与 :disabled 属性冲突 → 场景 5.2 A 改为合并 computed
无权限但按钮显示后端未给该角色下发标识，或标识与后端配置不一致
通用页面越权显示按钮数组权限 OR 语义问题 → 场景 5.1
