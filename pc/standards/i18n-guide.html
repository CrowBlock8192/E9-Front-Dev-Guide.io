国际化(i18n)实操规范 ​

机制原理、加载链路、热切换设计等见 i18n-architecture.md。本文只讲怎么用、怎么写才规范。

一、新页面接入(标准 5 步) ​

以 src/views/business/keystone/cfg_center/new_feat 为例：

Step 1：文案全部用 $t 包裹，中文原文即 key：

vue
<template>
	<a-form-item :label="$t('节点名称')" :rules="[{ required: true, message: $t('请输入节点名称') }]" />
	<a-button type="primary" @click="handleAdd">{{ $t('新增') }}</a-button>
</template>

Step 2：生成页面翻译模板：

bash
pnpm i18n:generate -- src/views/business/keystone/cfg_center/new_feat
# 加 --scan 可自动扫描页面中的中文文案生成初始词条
# 不想用工具就直接手动创建 locale/en.json

Step 3：补全 locale/en.json —— key 必须与代码中的中文原文逐字符一致：

json
{
	"节点名称": "Node Name",
	"请输入节点名称": "Please enter node name",
	"新增": "Add"
}

Step 4：校验 key 匹配：

bash
pnpm i18n:verify-keys        # 校验代码使用的 key 与翻译文件是否匹配
pnpm i18n:verify-keys --fix  # 自动补齐缺失 key

Step 5：提交前清理 + 通用文案上移：

bash
pnpm i18n:check-unused       # 清理未使用词条

同一文案在 3 个及以上页面使用 → 移入 src/locale/common/zh.json + en.json(启动即全量加载)，从页面级文件中删除。

二、代码写法规范 ​

vue
<template>
	<!-- 模板中直接用 $t -->
	<a-input v-model="form.name" :placeholder="$t('请输入名称')" />
</template>

<script setup>
import { useTranslation } from 'i18next-vue';
const { t } = useTranslation();

// script 中(提示语、校验消息等)
Message.success(t('保存成功'));

// 表格列配置统一用 translateColumns 递归翻译 title，不要手写遍历
import { translateColumns } from '@/locale';
const columns = computed(() => translateColumns(rawColumns, t));
</script>

规则：

#规则
1模板用 $t，script 用 useTranslation() 取 t
2面向用户的文案一律走翻译函数，禁止裸写中文(Arco 组件内置文案由框架自动切换，不用管)
3接口返回的多语言数据(菜单名等)由后端按 lang 请求头返回，前端不要写死映射
4表格列 title 用 translateColumns，保持响应式(computed 包裹)

三、翻译 Key 规范 ​

  1. 中文原文即 key：$t('节点名称') ↔ "节点名称": "Node Name"；
  2. key 与代码逐字符一致(含标点、空格)——历史 bug 最大来源，改了文案必须同步改 en.json；
  3. zh 环境 key 缺失时静默回退显示原中文，所以 zh.json 可省略；en.json 不允许缺 key；
  4. 结构化场景可用点号分类前缀：
分类前缀示例
表单字段表单字段."表单字段.桥梁名称": "Bridge Name"
按钮按钮."按钮.新增": "Add"
提示信息提示."提示.保存成功": "Saved successfully"
表格列表格列."表格列.操作": "Actions"
占位符占位符."占位符.请输入": "Please enter"
验证消息验证."验证.必填项": "This field is required"
状态状态."状态.启用": "Enabled"
  1. 词条 JSON 统一 UTF-8、2 空格缩进、文件末尾换行。

四、词条放哪(决策顺序) ​

新文案
 ├─ 大屏(screen)？ → 见第六节大屏规则
 ├─ ≥3 个页面使用？ → src/locale/common/{zh,en}.json(公共层)
 ├─ 仅本页面使用？ → 本页面 locale/{zh,}en.json(页面层，按路由自动懒加载)
 └─ 通用组件的文案？ → src/locale/basic_components/(已有组件词条集中在这)
  • 页面目录下建 locale/ 文件夹，页面内所有子组件(dialog/components)共用，无需手动 import；
  • src/locale/{lang}/业务路径.json 旧结构仅作兼容回退，禁止新增文件。

五、禁止事项 ​

#禁止原因/替代
1文案写死中文不包 $t英文环境直接漏翻
2代码 key 与 en.json 不一致翻译不生效且难排查 → 改完文案必跑 verify-keys
3en.json 缺 key英文环境显示中文
4页面专属文案放进 locale/common撑大全局首屏体积
5往 src/locale/{lang}/ 旧结构加文件仅兼容回退，新词条一律页面级或 common
6用 lStorage 工具写语言会加前缀和 JSON 包装，i18next 与 SSO 读不到 → 必须用 localStorage 裸 key arco-locale

六、大屏(screen)实操 ​

Step 1：先评估要不要翻译 —— 目标用户是多语言环境(如 shate)才建 locale；单一语言环境(如 road_634、road_351)不建任何 locale 文件，直接写中文。

Step 2：文案统一写 t('中文原文')，两种项目通用的兼容写法：

vue
<template>
	<!-- 需要翻译的项目显示英文；不需要的项目查找落空自动显示原中文，无需分支处理 -->
	<div>{{ t('项目概览') }}</div>
</template>

Step 3：需要翻译的项目按层放词条：

层位置放什么
大屏公共src/locale/screen/{zh,en}.jsonlayout、通用组件文案(导航、工具栏、星期/月份)
业务组件screen/library/<组件>/locale/仅含业务专有术语的卡片组件(按需建)
项目页面screen/pages/<项目>/<模块>/locale/该项目页面文案(shate 各模块)

Step 4：布局注意 —— 英文/阿语译文通常比中文长，大屏空间固定，卡片和标题要预留伸展空间；避免硬编码日期时间格式。

七、工具链速查 ​

命令用途时机
pnpm i18n:generate -- <页面路径>生成页面 locale 模板，--scan 扫描中文新建页面
pnpm i18n:generate:all批量为缺 locale 的页面生成模板批量补齐
pnpm i18n:verify-keys校验代码 key 与词条匹配，--fix 自动修复改文案后/提交前必跑
pnpm i18n:check-unused检测未使用词条定期清理
pnpm i18n:dedupe合并重复词条定期维护
pnpm i18n:migrate旧结构迁移到页面级仅历史页面
pnpm i18n:extract-components提取公共组件词条公共化时

八、提交前自查清单 ​

  • [ ] 页面所有面向用户的文案都包了 $t/t？
  • [ ] locale/en.json 已建且 key 与代码逐字符一致？
  • [ ] pnpm i18n:verify-keys 通过？
  • [ ] 通用文案(≥3 页面)已上移 locale/common？
  • [ ] 大屏项目：确认了是否需要翻译，不需要的没建 locale？
  • [ ] pnpm i18n:check-unused 无新增废弃词条？

九、问题速查 ​

现象处理
页面翻译不生效(英文环境仍显示中文)key 不一致 → 跑 pnpm i18n:verify-keys 核对
控制台 [i18n] Missing translation 警告开发环境缺失 key 提示，补 en.json
语言切换后部分文案没变刷新页面确认；仍异常按 i18n-architecture.md 调试手段排查
切换语言后接口数据没变接口未声明语言依赖 → 检查 i18n-refresh 的优先级注册(见 architecture 文档)
语言设置刷新后丢失检查是否有代码用 lStorage 写了 arco-locale
